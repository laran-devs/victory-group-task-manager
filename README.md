# Victory Tasks Task Manager — Panantukan Team (ЮНИТ hack 2026)

Victory Tasks Task Manager — это высокопроизводительная Kanban-система управления задачами с синхронизацией в реальном времени и событийно-ориентированной архитектурой (Event-Driven Architecture). Проект разработан командой Panantukan в рамках хакатона ЮНИТ 2026.

Система предназначена для управления рабочими процессами, автоматизации рутинных операций (контроль SLA, автоархивация, автоназначение) и отслеживания аналитики проекта. Решение полностью контейнеризовано и готово к быстрому развертыванию.

## Архитектура системы
Комплекс построен на базе микросервисного подхода и включает следующие компоненты:
1. **Frontend (React SPA)**: Пользовательский интерфейс, работающий через браузер.
2. **API Gateway (Nginx)**: Единая точка входа, проксирующая запросы и раздающая статические файлы. Полностью решает проблемы CORS.
3. **Backend (FastAPI)**: Асинхронный сервер, обрабатывающий REST-запросы и управляющий WebSocket-подключениями для обновления данных в реальном времени.
4. **База данных (PostgreSQL)**: Надежное персистентное реляционное хранилище данных проекта.
5. **Очередь сообщений (RabbitMQ)**: Брокер сообщений для обработки фоновых системных событий и интеграции с внешними источниками данных.

## Технологический стек

- **Frontend**: React 19, Vite, Tailwind CSS, Zustand, @dnd-kit
- **Backend**: Python 3.11, FastAPI, SQLAlchemy 2.0 (async), Uvicorn, aio-pika
- **База данных**: PostgreSQL 15, asyncpg
- **Брокер сообщений**: RabbitMQ 3
- **Инфраструктура**: Nginx, Docker, Docker Compose

## Инструкция по запуску проекта для Жюри

Для демонстрации проекта на локальном компьютере потребуется только Docker Desktop. Весь комплекс поднимается одной командой.

### 1. Системные требования
- Docker Desktop (включенная интеграция с WSL2 для ОС Windows).
- Docker Compose версии 2.0 или выше.

Примечание для пользователей Windows (WSL2): Если при сборке возникает сетевая ошибка загрузки образов (например, `lookup registry-1.docker.io: no such host`), выполните команду `wsl --shutdown` в командной строке перед запуском Docker Desktop, либо пропишите DNS `8.8.8.8` в настройках Docker Engine в интерфейсе программы. Это системный баг сетевого моста Windows.

### 2. Сборка и запуск контейнеров
Откройте терминал, перейдите в корневую директорию проекта и выполните команду:
```bash
docker compose up --build -d
```
Флаг `--build` гарантирует сборку актуальных образов, а `-d` запускает контейнеры в фоновом режиме.

Первый запуск может занять несколько минут, так как загружаются базовые образы операционных систем и устанавливаются зависимости. Последующие запуски происходят практически мгновенно.

### 3. Доступ к интерфейсам системы

После успешной инициализации всех контейнеров, сервисы будут доступны по следующим адресам:

- **Пользовательский интерфейс (Frontend)**: http://localhost/
- **Интерактивная документация API (Swagger UI)**: http://localhost/api/docs
- **Панель управления RabbitMQ**: http://localhost:15672/ (Логин/Пароль: `guest` / `guest`)

### 4. Тестовые учетные записи

Система автоматически инициализирует базу данных базовым набором тестовых данных (проекты, задачи, колонки, сотрудники).

## Основной функционал

- **Real-Time Kanban-доска**: Перемещение карточек задач с помощью Drag & Drop мгновенно синхронизируется у всех подключенных пользователей через протокол WebSocket.
- **Динамическое управление колонками**: Администраторы могут добавлять, переименовывать, перемещать и удалять настраиваемые колонки непосредственно из панели управления.
- **Правила автоматизации рабочих процессов**:
  - **Автоназначение**: Автоматическое назначение ответственного (Lead PM) при присвоении задаче статуса "Критический".
  - **SLA-индикаторы**: Подсветка просроченных задач и визуализация нарушенных сроков (дедлайнов).
  - **Автоархивация**: Автоматическое удаление задачи с доски через 1.5 секунды после перемещения в колонку "Выполнено" (Done).
- **Ролевая модель доступа**: Разграничение прав между сотрудниками, администраторами и суперпользователями (RBAC).
- **Фоновые процессы и мониторинг**: Интеграция с RabbitMQ для приема системных событий с возможностью просмотра логов потока сообщений через панель администратора.
- **Генерация отчетов**: Автоматическое формирование сводок по метрикам эффективности в системе.

Для полной остановки работы всего комплекса:
```bash
docker compose down
```
